## Needs the owner before going live

The new app code reads `profiles.sessions_revoked_at` and calls `update_order_details`, so deploy order matters (if the code goes first, sign-in keeps working through a fallback but sign-out revocation is off and `/api/health` returns 503 "database migrations pending" until the migration is applied; `update_order_details` is unavailable); and until it is applied the old database lets anyone call `track_order` directly (skipping the app's rate limit) and lets staff write payments/orders outside the audited functions. Fix: `supabase db push` (or paste the file into the Supabase SQL editor), then deploy. The production server also refuses to start without `AUTH_SECRET` (32+ characters) and `IP_HASH_SALT` (16+ characters).
